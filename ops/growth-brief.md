## Phrases to target next, in priority order

Rows 8 to 12 of this week's plan come first. These are the next guides, one per run, after the plan and backlog guides (TV USB, soft vs burned, remove SDH). Each is a new guide unless stated.

1. **"vlc subtitles not showing", "vlc srt not working"**. New guide `vlc-subtitles-not-showing`, title "VLC not showing subtitles? Check these five things". Distinct from the existing VLC delay guide (that one is timing; this is "nothing appears"). Facts: the subtitle track may be off (Subtitle menu > Sub Track); Subtitle > Add Subtitle File loads any .srt without a name match; auto-loading needs the same folder and the same base name as the video; Windows hides extensions, so `Movie.srt.txt` is common; a file that is not UTF-8 can fail or show wrong letters; when casting to a Chromecast, SRT often does not show (see 3). Tools: /srt-validator/, /fix-subtitle-encoding/, /vtt-to-srt/ (renamed files). Link the VLC delay guide and the weird-characters guide.
2. **"plex subtitles not showing", "plex external srt not detected"**. New guide `plex-subtitles-not-showing`. Facts (Plex forum checklist thread "External subtitles (.srt) troubleshooting checklist"): external subtitles need the "Local Media Assets" source enabled for the library's agent; name as `Movie (2020).en.srt` next to the video; after a change run Refresh Metadata and Analyze on that item (a full library refresh sometimes does not pick it up); a file named .srt may really be ASS or VTT inside; some players (Apple TV, Fire TV reports) drop external SRT in Direct Play, so test on another client. Tools: /srt-validator/, /ass-to-srt/, /vtt-to-srt/, /fix-subtitle-encoding/. Link the Plex sync guide and the Jellyfin guide (same naming idea).
3. **"chromecast subtitles not showing", "cast srt subtitles"**. New guide `chromecast-subtitles-not-showing`. Facts: Google Cast's media page (developers.google.com/cast/docs/media) lists only TTML, WebVTT and CEA-608/708 for subtitles, and says subtitle files must be served with CORS. So a plain SRT usually needs converting to WebVTT; some apps convert for you, others do not. User reports: letters outside plain English vanished until the file was saved as UTF-8. Tools: /srt-to-vtt/ (the example on that page shows the WEBVTT header and dot times), /srt-to-ttml/, /fix-subtitle-encoding/. Check in code that VTT output is UTF-8 before saying so.
4. **"html5 video srt subtitles", "track element srt not working"**. New guide `add-subtitles-to-html5-video`. Audience: people building a web page. Facts: the `<track>` element takes WebVTT, not SRT; a VTT file starts with a `WEBVTT` line and uses dots in times; give a 5-line `<video>` + `<track kind="subtitles" srclang="en" label="English" default>` sample; a track on another domain needs `crossorigin` on the video and CORS on the server; check the browser's Network tab to see if the .vtt is requested at all. Tools: /srt-to-vtt/, /preview-subtitles-with-video/.
5. **"subtitles out of sync halfway through", "subtitles fine at first then off"**. New guide `subtitles-out-of-sync-partway`. Facts: if the offset jumps at one point, the video is a different cut (ad breaks removed, an extra scene, a recap); if it grows steadily, it is frame rate (link the 23.976 guide, don't repeat it). Fix for a jump: shift only from the line where it goes wrong. Tools: /shift-subtitles-from-a-line/ (our tool nobody else explains well), /sync-subtitles/ for two-point fixes. Link the general out-of-sync guide.
6. **"kodi subtitles out of sync", "kodi subtitle offset"**. New guide `kodi-subtitles-out-of-sync`. The boss cut this for missing facts; here is what was found: Kodi has a subtitle offset during playback (in the player's subtitle settings), which users like for quick fixes; nobody documents a setting that applies the offset to every player, so the reliable route is to fix the file and save it next to the video. If the offset grows over the film, it is frame rate. Write only these facts; if unsure of a menu name, describe it in words.
7. **"subtitles showing twice", "duplicate subtitle lines"**. New guide `subtitles-showing-twice`. Causes: two tracks on at once (an embedded track plus an external file), or the file itself repeats cues (merged downloads). Tools: /remove-duplicate-subtitles/, /merge-subtitles/ (only if relevant), /srt-validator/ (overlaps).
8. **"srt shows {\an8}", "remove font tags from srt"**. New guide `remove-tags-from-subtitles`, only if /subtitle-cleaner/ or another tool removes ASS override tags and `<font>` tags (read `stripTags` in src/lib/subs.ts and the cleaner options first). If no tool does it, skip this row.
9. **"mx player subtitles out of sync"** (large Android audience). New guide `mx-player-subtitle-sync`. Facts are thin: third-party pages say the subtitle menu has a Synchronization slider, and a forum user mentions a "subtitle speed" option for drift. Menu names vary by version, so describe them loosely, and make the core of the guide "fix the file once so it plays right on the phone, the TV and the laptop". Lowest priority.
