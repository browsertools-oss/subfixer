## Facts for this week

The workers can't search the web. Use only the facts here, in ops/growth-brief.md and in the code. Write "a common cause is" or "some users report" for user reports. Never name a competitor site in copy.

MKV facts (Matroska spec, checked 11-22-2026):
- An MKV holds video, audio and subtitle tracks. Text subtitle tracks have the codec IDs `S_TEXT/UTF8` (SRT text), `S_TEXT/ASS`, `S_TEXT/SSA` and `S_TEXT/WEBVTT`. Picture tracks are `S_HDMV/PGS` (Blu-ray), `S_VOBSUB` (DVD) and `S_DVBSUB`: those are images, so they can't be saved as text without OCR.
- Burned-in subtitles are part of the picture: no tool can extract them as a track.
- Subtitle lines are spread through the whole file next to the video frames, so the tool has to read the file from start to end. It reads 1 MB at a time and keeps only the subtitle text, so a 4 GB film needs no more memory than a small one. Reading a whole film takes a while; say "a full film can take a minute or more", nothing faster.
- The desktop route (for the guide): the free MKVToolNix, `mkvmerge -i movie.mkv` lists track IDs, `mkvextract tracks movie.mkv 3:subs.srt` saves track 3. VLC lists embedded tracks under Subtitle > Sub Track but cannot save them.
- Matroska stores language as a 3-letter code (eng, fre, ger, spa). Plex and Jellyfin read 2- and 3-letter codes in names like `Movie (2020).eng.srt` (keep the claim to "a name like Movie (2020).eng.srt next to the video", as the Plex guide already says for .en).

TV facts (row 4), web, 11-22-2026:
- LG's help page "LG TV: USB video subtitle issue" says: video and subtitle names must be identical (a blank space difference breaks it); open the .srt in Notepad, Save As, Encoding ANSI; the stick should be FAT32 or NTFS; if the video itself fails, the TV may not support its codec.
- Samsung community forum, user reports: the same base name and the same folder fixed it for several users; Windows hides extensions, so a file can really be `Movie.srt.txt` (turn on "File name extensions" in File Explorer's View menu); some users report USB works while network playback (DLNA, NAS) does not show the external file.
- Sony support (Android and Google TV models): same folder, same name, lowercase extension (`.srt`, not `.SRT`).
- "ANSI" in Notepad means the PC's old code page: Windows-1252 on US and Western European Windows, Windows-1251 on Cyrillic Windows. /fix-subtitle-encoding/ can now save as these (shipped 11-22, commits 1b7d1ef and 02f6183; check the "Save as" select in src/components/Tool.astro with grep before describing it).
- Picture subtitles (.sup, PGS) need a text SRT for most TVs: /sup-to-srt/.

Code facts (grep the line before you quote it): `parse` in src/lib/subs.ts detects the format from content, not the name. `build(captions, 'srt' | 'vtt' | ...)` in src/lib/subs.ts line 175 writes files (SRT and VTT with CRLF). `stripTags` (line 116) removes `<i>`, `<font>` and `{\an8}`; the cleaner's "tags" option runs it. `fixCommon` (line 330) has the dupes, SDH and tags options. `validate` (line 421) has the overlap, zero, short and order checks.

## MKV spec (rows 1 and 2)

1. Reader. In src/lib/mkv.ts export `interface MkvSource { size: number; read(offset: number, length: number): Promise<Uint8Array> }` and `const CHUNK = 1 << 20`. Inside, a buffered reader: keep one window `{ start, bytes }`; `get(off, len)` returns a subarray when `[off, off+len)` is inside the window, else sets the window to `await src.read(off, Math.max(len, CHUNK))` (clipped to `size`). Never ask `src.read` for more than `Math.max(len, CHUNK)`; video blocks are skipped by moving the position, never read. The browser source is `{ size: file.size, read: (o, l) => file.slice(o, o + l).arrayBuffer().then((b) => new Uint8Array(b)) }`.
2. EBML. Element ID: the number of leading zero bits of the first byte + 1 is the length (1 to 4); keep the marker bit, so IDs compare to the hex values below. Size: same length rule (1 to 8), drop the marker bit; if all value bits are 1 the size is unknown. Read IDs and sizes from a `get(pos, 12)` (clip at the end of the file). IDs: EBML header `0x1A45DFA3`, Segment `0x18538067`, Info `0x1549A966`, TimestampScale `0x2AD7B1` (default 1000000), Tracks `0x1654AE6B`, TrackEntry `0xAE`, TrackNumber `0xD7`, TrackType `0x83` (17 = subtitle), CodecID `0x86`, CodecPrivate `0x63A2`, Language `0x22B59C` (default "eng"), Name `0x536E`, FlagDefault `0x88`, FlagForced `0x55AA`, ContentEncodings `0x6D80` > ContentEncoding `0x6240` > ContentCompression `0x5034` > ContentCompAlgo `0x4254` (default 0 = zlib, 3 = header stripping) and ContentCompSettings `0x4255`; ContentEncryption `0x5035` means encrypted. Cluster `0x1F43B675`, Timestamp `0xE7`, SimpleBlock `0xA3`, BlockGroup `0xA0`, Block `0xA1`, BlockDuration `0x9B`.
3. Scan, flat loop. `export async function scanMkv(src: MkvSource, onProgress?: (done: number, total: number) => void, signal?: AbortSignal): Promise<{ tracks: MkvTrack[]; cues: Map<number, MkvCue[]>; skipped: number }>`. If the first 4 bytes are not `1A 45 DF A3`, throw `new Error('This is not an MKV or WebM file.')`. `pos = 0`; loop while `pos < size`: read the header. Segment and Cluster: enter (pos = data start; unknown size is fine); on Cluster set `clusterTime = 0`. Info and Tracks: read the whole element, parse its children, skip past it. Timestamp: read, set `clusterTime`. SimpleBlock: `get` the first 8 bytes of its data, read the track number (a size-style vint); if it is a text subtitle track, read the whole block and add a cue (duration unknown), else skip. BlockGroup: `get` its first 16 bytes, find the Block child and its track number the same way; if ours, read the whole group and use Block and BlockDuration, else skip. Everything else (EBML header, SeekHead, Void, CRC-32, Cues, Attachments, Chapters, Tags): skip by size; if its size is unknown, stop. Call `onProgress(pos, size)` at most once per CHUNK and `signal?.throwIfAborted()` there too. Block data: track vint, then a signed 16-bit big-endian relative time, then a flags byte; if `(flags & 0x06) !== 0` (lacing), count it in `skipped` and drop it. Payload: if the track uses zlib, `unzlibSync` from fflate (lazy `await import('fflate')`); if header stripping, put the settings bytes in front. Times in ms: `Math.round((clusterTime + rel) * scale / 1e6)`, end from BlockDuration the same way. A cue with no duration ends at the next cue's start on that track, or start + 3000 for the last one.
4. Output. `export interface MkvTrack { number: number; codec: string; language: string; name: string; isDefault: boolean; forced: boolean; kind: 'srt' | 'ass' | 'vtt' | 'picture' | 'other'; encrypted: boolean }` (kind from the codec: `S_TEXT/UTF8` srt, `S_TEXT/ASS` and `S_TEXT/SSA` ass, `S_TEXT/WEBVTT` vtt, `S_HDMV/PGS`, `S_VOBSUB`, `S_DVBSUB` picture). Only srt, ass and vtt tracks get cues; encrypted tracks get none. `export function trackFile(track, cues, codecPrivate): { name: string; text: string }` where the name ends `.<language>.srt`, `.ass` or `.vtt`: srt uses `build(captions, 'srt')`, vtt uses `build(captions, 'vtt')` (captions with text decoded as UTF-8, trailing newlines trimmed, sorted by start). ASS: the payload is `ReadOrder,Layer,Style,Name,MarginL,MarginR,MarginV,Effect,Text`; split on commas, the text is everything after the 8th comma; sort by ReadOrder; write the CodecPrivate text (it holds [Script Info] and the styles; if it has no `[Events]` line, add `[Events]` and `Format: Layer, Start, End, Style, Name, MarginL, MarginR, MarginV, Effect, Text`), then one `Dialogue: Layer,H:MM:SS.cc,H:MM:SS.cc,Style,Name,MarginL,MarginR,MarginV,Effect,Text` line per cue, CRLF line ends.
