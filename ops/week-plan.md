## Facts for this week

The workers can't search the web. Use only the facts here, in ops/growth-brief.md and in the code. Write "a common cause is" or "some users report" for user reports. Never name a competitor site in copy.

MP4 facts (ISO base media format, checked 11-24-2026):
- An MP4 (also .m4v, and Apple's .mov) stores its index in a `moov` box and the audio and video data in an `mdat` box. The index says where every sample is, so a tool can read just the subtitle bytes and never the video. Say "it reads the file's index, then only the subtitle lines"; don't promise a time.
- Text subtitle tracks in MP4 are "MPEG-4 Timed Text" (codec `tx3g`, also called mov_text; ffmpeg writes this) and sometimes WebVTT (`wvtt`). Apple QuickTime files may use `text`. Closed captions (`c608`) and TTML (`stpp`) exist but are rare in downloads; this tool lists them as not supported.
- Many MP4s have no subtitle track: phone recordings, most screen recordings, and many downloads where the subtitles were burned into the picture. Burned-in text can't be pulled out by any tool as a track.
- Streaming downloads are often "fragmented" MP4 (the index is spread through the file in `moof` boxes). This tool does not read those and says so.
- The desktop route, for the guide: the free ffmpeg, `ffmpeg -i movie.mp4 -map 0:s:0 subs.srt` saves the first subtitle track.

MP4 on TVs (web, 11-24-2026, user reports only; write "some users report"):
- TVs differ in which subtitle formats inside an MP4 they show. Some users report embedded MP4 subtitles that never appear on the TV, while an external .srt with the same name as the video shows fine.
- Casting or streaming from a computer to a TV (VLC's renderer, DLNA, Chromecast) often drops the subtitle track; some users report the subtitles show on the laptop and not on the TV.
- Roku and Jellyfin users report the same: embedded MP4 subtitles not showing, external SRT working. One forum answer suggests checking whether the track is flagged "forced".
- The common fix: save the track as an SRT named exactly like the video, in the same folder (rules already in /guides/tv-subtitles-not-showing-usb/; link it, don't repeat it).

Track flag facts (for row 5, growth brief 11-23): a forced track holds only the lines for foreign-language speech and on-screen signs, so it looks "almost empty" when saved; SDH (subtitles for the deaf and hard of hearing) adds speaker names and sounds such as [door slams]; MKV flags tracks as default and forced. After row 3 the extractor shows "(default)" and "(forced)" next to the track name; check src/components/MkvExtract.astro with grep before writing that.

Shift tool facts (for `qa` 27): /shift-subtitle-timing/ asks "The subtitles show up" with the choice "Too late" or "Too early", then "By how many seconds" (src/components/Tool.astro lines 218 to 225). There is no minus sign and no milliseconds field. Subtitles that come 2 seconds after the speech: pick "Too late", enter 2.

## MP4 spec (rows 1 to 3)

1. File and exports. New file src/lib/mp4.ts. `import type { MkvSource, MkvTrack, MkvCue } from './mkv.ts';` Local consts `MAX_MOOV = 64 << 20` and `MAX_SAMPLE = 1 << 20`. Export `async function scanMp4(src: MkvSource, onProgress?: (done: number, total: number) => void, signal?: AbortSignal): Promise<{ tracks: MkvTrack[]; cues: Map<number, MkvCue[]>; codecPrivate: Map<number, string>; skipped: number }>`, the same shape as `scanMkv`, so the page and `trackFile` work unchanged. `codecPrivate` maps every listed track number to ''. Call `src.read` directly (no Reader class needed): the reads are box headers (16 bytes), the moov box once, and each subtitle sample. Read numbers with a `DataView`; a 64-bit value is `hi * 2 ** 32 + lo`.
2. Boxes. A box header at `pos`: read 16 bytes. `size` = uint32 at 0, `type` = 4 ASCII characters at 4. If size is 1, the real size is the uint64 at 8 and the header is 16 bytes; if size is 0, the box runs to the end of the file (or its parent); otherwise the header is 8 bytes. If size is smaller than the header, stop (damaged file). Write one helper `kids(buf: Uint8Array): { type: string; data: Uint8Array }[]` that walks boxes inside a buffer with the same rule, and `find(buf, ...path)` that follows a path such as `find(trak, 'mdia', 'minf', 'stbl', 'stsd')` and returns the data or null. "Full boxes" (tkhd, mdhd, hdlr, stsd, stts, stsz, stsc, stco, co64) start with 1 version byte and 3 flag bytes; the offsets below count from the start of the box data, version byte included.
3. Top level and tracks. The first box's type must be one of `ftyp`, `moov`, `mdat`, `free`, `skip`, `wide`; else throw `new Error('This is not an MP4, MKV or WebM file.')`. Walk top-level boxes from 0; skip each by its size (the `mdat` is never read). On `moov`: if its size is over MAX_MOOV throw `new Error('This MP4 index is too large to read.')`; read its whole data, parse, stop walking. No moov: throw `new Error('This MP4 has no index (moov box). The file may be cut short or still downloading.')`. A child `mvex` in moov: throw `new Error('This MP4 is split into fragments, as many streaming downloads are. This tool reads regular MP4 files only.')`. For each `trak`: tkhd: version = byte 0, flags = bytes 1 to 3, track ID = uint32 at 20 if version 1 else 12. mdia/mdhd: timescale = uint32 at 20 (v1) or 12 (v0); language = uint16 at 32 (v1) or 20 (v0), three 5-bit letters: `String.fromCharCode(((l >> 10) & 31) + 0x60, ((l >> 5) & 31) + 0x60, (l & 31) + 0x60)`. mdia/hdlr: handler = 4 characters at 8. List only tracks whose handler is `text`, `sbtl`, `subt` or `clcp`. mdia/minf/stbl/stsd: the codec is 4 characters at 12 (entry count at 4, the first entry box starts at 8). Kind: `tx3g` and `text` give 'srt', `wvtt` gives 'vtt', anything else 'other'; `encs` or `enct` mean encrypted (kind 'other', `encrypted: true`). MkvTrack: `{ number: trackId, codec, language, name: '', isDefault: false, forced: false, kind, encrypted }`. Sort tracks by number.
4. Samples (only kinds 'srt' and 'vtt'). From stbl: stts (count at 4, then pairs of uint32 sampleCount, sampleDelta from 8), stsz (uniform size at 4, sample count at 8; if the uniform size is 0, one uint32 per sample from 12), stsc (count at 4, then triples firstChunk, samplesPerChunk, descriptionIndex from 8), stco (count at 4, uint32 offsets from 8) or co64 (uint64 offsets from 8). If one of them is missing, list the track with no cues. Times: walk stts with a running tick count `t`; sample start = `Math.round(t * 1000 / timescale)`, end = `Math.round((t + delta) * 1000 / timescale)`. Offsets: for chunk `c` (0-based), samplesPerChunk comes from the last stsc entry whose firstChunk is at most `c + 1`; the first sample of a chunk sits at the chunk offset, each next sample at the previous offset plus its size.
